- 기준: 사용자 로직 수정안 + 어긋난 4가지에 대한 Claude 의견(사용자 채택, 2026-10-09) + 기존 확정 사항

- 금액·기한 표기: "(설정값)"은 운영자가 바꿀 수 있는 값이고, 예시 숫자는 확정이 아니다.

## 1. 법 확인 결과 (최우선)

### 1-1. 확인한 사실
| 근거 | 내용 |
|---|---|
| 금융위원회 설명자료 (2024-06-25) | 플랫폼·유통업체 본사가 전자적 방법으로 대가 정산을 대행하거나 매개하면 전자지급결제대행업(PG) 등록이 필요하다. 미등록은 형사처벌 대상이다. 단, 외부 PG사가 정산을 대행하고 플랫폼은 판매자 계좌정보 등만 넘기면 등록이 필요 없다 |
| 금융위 법령해석 (회신 160862) | 통신판매중개업자가 일반상품 거래의 결제대금 정산에 관여하면 PG 등록이 필요하다 |
| 개정 전자금융거래법 (2025-12-16 공포, 2026-12-17 시행) | PG 정의를 "제3자 간 대가를 수수하고 정산을 대행하는 것"으로 정리했다. 통신판매중개 등을 하면서 부수적으로 대가를 수수·정산하는 경우는 제외한다. 다만 "부수적"의 범위는 정해지지 않았고, 판매대금 전체를 받아 정산하는 구조가 이 예외에 들어가는지는 불분명하다 |
| 같은 개정법 | PG는 정산대상금액을 외부기관(신탁·예치·보증보험)으로 관리해야 한다(60% → 80% → 100%). 정산금을 다른 용도로 쓰면 10년 이하 징역 등 처벌을 받는다 |
| 전자상거래법 제24조와 시행령 | 통신판매업자(사업자)가 현금 선지급을 받으면, 1회 결제가 10만원 이상일 때 구매자가 결제대금예치(에스크로)나 소비자피해보상보험을 고를 수 있게 해야 한다. 결제대금예치업자는 전자금융거래법에 따른 금융위 등록이 필요하다 |
| 번개장터 사례 | 안전결제는 제3의 금융기관이 대금을 보관하고 거래가 끝나면 판매자에게 정산하는 에스크로 방식이다. 2024년 8월 결제를 안전결제로 일원화했다 |

### 1-2. 써보니에 적용하면 (해석, 법률 자문 아님)
- 지금 계획한 "구매자가 빅플래닛 계좌로 입금 → 써보니가 보관 → 판매자에게 수수료를 빼고 송금, 또는 구매자에게 체험료를 빼고 환불"은 2026-12-16까지 시행 중인 현행법 기준으로 PG 등록 대상일 가능성이 높다. 미등록 영업은 형사처벌 대상이다.
- 2026-12-17 이후에는 통신판매중개에 부수하는 정산 예외가 생긴다. 그러나 써보니처럼 판매대금 전액을 받아 두는 구조가 예외에 들어가는지는 확정할 수 없다.
- PG 등록에는 자본금(소규모 기준도 수억 원대), 인력·설비, 정산자금 외부관리가 필요하다. 베타 단계에서는 현실성이 낮다.
- 빅플래닛이 사업자로서 직접 파는 상품(한군 계정 205개)은 판매자가 통신판매업자다. 10만원 이상을 현금으로 미리 받으면 구매안전서비스 제공 의무를 따져 봐야 한다.

| 4. 연습 거래 | 돈은 오가지 않고 흐름·화면·계산만 시험한다 | 없음 | - | 베타 시험에 바로 쓸 수 있다 |

### 1-4. 권장
1. 개발은 결제 방식과 분리해 만든다. 거래 상태, 계산, 원장은 공통으로 두고 "돈을 누가 받는가"만 설정으로 바꿀 수 있게 한다.
2. 베타는 4번(연습 거래)으로 바로 시작한다. 실거래가 필요하면 2번(판매자 직접 입금)으로 연다.
3. 3번(빅플래닛 계좌 정산)은 핀테크 전문 변호사 자문을 받거나, 금융규제·법령해석포털(better.fsc.go.kr)에 법령해석이나 비조치의견서를 신청해 확인한 뒤에만 쓴다.
4. 1번(외부 에스크로)은 계속 찾아본다. 은행 에스크로나 중고거래 전문 에스크로처럼 다른 기관도 확인한다.

## 2. 확정 원칙
1. 구매자는 먼저 결제하고, 체험한 뒤 구매나 반납을 고른다.
2. 구매 확정이면 체험료는 0원이다. 같은 상품대금을 다시 받지 않는다.
3. 반납이면 최초 결제금에서 체험료, 수수료, 구매자 부담 택배료를 빼고 환불한다.
4. 정상 구매와 정상 반납은 똑같이 정상 체험으로 인정한다.
5. 거래 상태, 돈(결제·환불·정산), 활동 등급, 신뢰는 따로 관리한다.

## 3. 어긋났던 4가지 확정 내용 (Claude 의견 채택)
| | 확정 내용 |
|---|---|
| A. 수수료 | 수수료는 최초 결제금의 3%(설정값, 특정 기간 0% 가능)다. 구매하면 판매자 입금액에서, 반납하면 구매자 환불금에서 뺀다 |
| B. 최초 결제금 | 상품가 + 구매자 부담 발송비를 한 번에 받는다. 화면에서는 두 금액을 나눠 보여 준다 |
| C. 무응답 | 체험 기한까지 고르지 않으면 "확인 필요"로 바꾸고 안내한다. 그 뒤 72시간(설정값) 안에도 답이 없으면, 신청할 때 미리 알린 대로 구매 확정한다. 기한을 넘겨 반납하면 다음 구간 체험료를 적용한다(예: 24시간 구간에서 25시간째 → 48시간 요금). 가장 긴 구간을 넘기면 유예가 끝난 뒤 구매로 처리한다 |
| D. 후기 | 거래 평가(별점 1~10 + 정해진 문구 필수, 예시 문장·직접 쓰기 선택)와 써보니 후기(체험 전 질문의 답 + 구매·반납 이유 + 써보고 알게 된 점 + 어울리는 사람)로 나눈다 |

## 4. 계산식
- 최초 결제금 = 상품가 + 구매자 부담 발송비
- 수수료 = 상품가 × 수수료율(0.1% 단위, 원 단위 처리 방식은 결정 대기)
- 구매하면
  - 구매자 추가 부담 0원
  - 판매자 입금 = 상품가 − 수수료 + 발송비(판매자가 보낸 경우)
- 반납하면
  - 환불 = 최초 결제금 − 체험료 − 수수료 − 구매자 부담 발송비 − 환불금에서 뺄 반송비
  - 판매자 입금 = 체험료 + 발송비 보전분
  - 구매자가 택배사에 직접 낸 반송비는 다시 빼지 않는다
- 안전장치
  - 체험료 + 수수료 + 공제 택배료가 결제금보다 크면 "확인 필요"로 넘긴다. 부족액을 자동 청구하지 않는다(상품 등록 때 이미 막고 있다)
  - 같은 거래의 환불·정산은 한 번만 처리한다. 부분 환불이 있었으면 그 금액을 빼고 계산한다
  - 환불 완료는 실제 송금을 확인한 뒤에 표시한다

## 5. 거래 상태
```
신청(조건 스냅숏, 체험 전 질문 최대 3개)
 → 결제 확인
 → 발송 대기 → 배송 중 → 수령 확인(체험 시작)
 → 체험 중(연장 가능)
 → ┬ 구매 확정 → 구매 정산 → 구매 완료
   ├ 반납 신청 → 반송 대기 → 반송 중(송장·인계일) → 판매자 수령·검수 → 환불액 확정 → 환불·정산 → 반납 완료
   └ 무응답 → 확인 필요 → (72시간 무응답) 구매 확정
분쟁: 진행 상태와 별도. 분쟁 접수 → 정산 보류 → 양측 자료 → 결과 확정 → 정산 재개
```
- 수령 확인: 구매자가 "받았어요"를 누른다. 누르지 않으면 발송 후 N일(설정값)이 지나 자동으로 수령 처리하고, 이견은 운영자가 판단한다.
- 반송 기한: 택배 인계일로 판단한다. 송장번호와 접수 영수증 사진을 받는다.
- 연장: 이미 전액을 결제했으므로 추가 입금은 없다. 다음 구간과의 체험료 차액만큼 환불 예정액이 줄어든다. 판매자가 정한 가장 긴 구간까지만 되고, 승인 없이 자동으로 된다.
- 상태가 바뀔 때마다 그 상품 채팅방에 시스템 메시지를 남긴다. 채팅방이 주문 기록 역할을 한다.
- 배송지는 결제 확인 뒤에만 판매자에게 보인다.

## 6. 후기
| 구분 | 누가 | 내용 |
|---|---|---|
| 거래 평가 | 구매자와 판매자가 서로 | 별점 1~10, 정해진 문구(필수). 예시 문장, 직접 쓰기(선택) |
| 써보니 후기 | 수령이 확인된 체험 거래의 구매자만 | 체험 전 질문의 답, 구매·반납 이유, 써보고 알게 된 점 한 줄, 어울리는 사람 |

- 탭은 보낸 후기, 받은 후기, 써보니 후기로 나눈다. 판매자 채널에 모두 보인다.
- 서로 쓰는 거래 평가는 둘 다 썼거나 7일이 지나면 동시에 공개한다.
- 문구는 점수에 맞게 칭찬 문구와 아쉬운 문구로 나눠 보여 준다.
- 구매 여부나 좋은 평가에는 보상을 주지 않는다.
- 개인에게 안 맞아서 반납한 것("무거워서")을 판매자 잘못으로 처리하지 않는다.
- 인증 표시는 "체험 거래 인증 · 체험 기간 2일"처럼 확인할 수 있는 사실만 적는다.
- 써보니 후기는 같은 모델끼리 모아서 보여 준다. 사양, 상태, 체험 시점을 함께 적는다.

## 7. 활동 등급 (구매자·판매자 따로)
- 이름: 써린이 → 써본이 → 써잘알 → 써고수 → 써신(5단계, 경계는 설정값)
- 경험치
  - 구매 완료나 정상 반납 완료마다 구매자와 판매자가 각각 1점
  - 체험 전 취소, 별점, 가격, 후기에는 점수가 없다
  - 거래번호·회원·종류 기준으로 한 번만 준다
- 활동 등급은 신뢰나 노출 순위와 연결하지 않는다.

## 8. 신뢰 (확인된 사실만)
- 판매자: 발송 약속 준수, 설명과 실제의 일치, 구성품 정확
- 구매자: 반송 약속 준수, 구성품 반환, 책임이 확인된 훼손
- 표시 예: "반송 약속 준수 9/10회 · 최근 90일". 기록이 없으면 "기록 없음"으로 표시한다.
- 정상 반납, 낮은 후기, 분쟁 신청만으로는 감점하지 않는다.

## 9. 실거래 시세와 분석
- 시세: 실제 판매 완료 거래만 쓴다. 중앙값, 범위, 건수, 기간, 기준 시점을 보여 준다. 표본이 적으면 "비교 거래 부족"으로 표시하고, 소수 표본으로 저렴함 배지를 주지 않는다. 체험료는 시세에 넣지 않는다.
- 체험료는 비율(하루 체험료 ÷ 상품가)로 모델과 상품군 참고값을 보여 준다.
- 판매자 구매 전환율과 반납 이유 분석은 판매자 본인만 본다. 반납 후 다음 검색 제안은 사용자가 고를 때만 적용한다.

각 단계는 복사 DB에서 시험한다. PC·모바일 화면에서 모든 버튼을 눌러 보고, 문서의 필수 검수 사례를 자동 시험으로 만든다.

## 11. 결정 필요
1. 결제 방식: 베타를 연습 거래로 할지, 판매자 직접 입금으로 할지. 빅플래닛 계좌 정산을 위한 법률 자문이나 비조치의견서를 신청할지
2. 수수료 원 단위 처리: 반올림, 올림, 버림
3. 설정값: 체험료(판매자 입력), 발송·반송비 부담 주체, 수령 자동 처리 N일, 반송·검수·환불 기한, 무응답 유예 72시간, 정산일 D+N, 등급 경계, 통계 최소 건수
4. 예외 처리 기준: 취소, 하자, 설명 불일치, 조기 반납, 훼손 배상
5. 카카오 전용 카드 공유가 필요한지(개발자 앱 등록)
