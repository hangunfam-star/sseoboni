# 써보기 데이터 예시 노출 검토 — 2026-10-13

## 목적
- 써보니의 핵심은 "써보고 결정". 지금은 실제 써보기 기록이 없어 메인에서 이 가치가 안 보인다.
- 예시 데이터로 메인 모듈을 먼저 만들어 보면, ① 사용자에게 써보기 가치를 보여 주고 ② 어떤 데이터를 실제로 모아야 하는지(개발 방향)를 정할 수 있다.
- 시안 그림: reports/2026-10-13-써보기데이터-예시노출-시안.png

## 법적 확인(실제 확인 범위)
- 표시·광고의 공정화에 관한 법률 제3조가 거짓·과장·기만적 표시·광고를 금지한다. 공정위 「추천·보증 등에 관한 표시·광고 심사지침」은 사업자가 관여한 후기를 소비자 독자 의견처럼 보이게 하면 기만적 광고로 본다(2025년 개정·안내서 배포, 시정명령·과징금 사례 있음).
- 따라서 가짜 숫자·가짜 후기를 "실제 기록처럼" 보이면 안 된다. 모든 예시에는 **예시 표시를 눈에 띄게** 붙이고, 실제 숫자처럼 읽히는 문구(예: "지금까지 1,284명이 써봤어요")는 쓰지 않는다.
- 사업자가 직접 쓴 가짜 후기에 대한 세부 판단 기준은 이번 검색으로 확인하지 못했다(원문 지침 확인 필요).
- 근거: 신&김 뉴스레터(지침 개정안), 아주경제 2025-12-02(지침 개정·배포), 데일리안(미표시 처벌).

| 모듈 | 보여 줄 데이터(예시) | 표시 방법 | 판단 |
|---|---|---|---|
| ① 일반 중고 vs 써보니 비교 | 사진만 보고 결정 ↔ 직접 써보고 결정, 하자 다툼 ↔ 반납·환불, 판매자 말 ↔ 써보기 후기, 구성품 운 ↔ 체크리스트 검수 | 기능 설명이라 예시 표시 불필요 | **바로 적용 권장**(가짜 숫자 없음) |
| ② 숫자 띠 | 써보고 결정한 사람 수, 써본 뒤 구매 비율, 평균 써본 기간, 평균 써보기 스타 | 제목 옆 "예시" + 아래 "서비스 시작 전 예시 숫자예요. 실제 기록이 아니에요." | 조건부(예시 표시 필수). 실제 숫자가 기준 이상 모이면 자동으로 실제 숫자로 교체 |
| ③ 써보기 후기 카드 | 모델명, 써본 시간·체험료, 결과(구매/반납), 써보기 스타, 확인한 점 칩, 한 줄 후기 | 카드마다 "예시 후기" 표시, 작성자 이름·사진 없음 | 조건부(예시 표시 필수). 실제 후기가 생기면 실제를 앞에, 예시는 뒤로 → 일정 수 이상이면 예시 제거 |
| ④ 상품 상세: 모델별 써본 결론 | 구매/반납 비율 막대, 가장 많이 확인한 점, 반납 이유 1위, 평균 써본 기간 | "예시" 표시 | 조건부. 상품 상세는 구매 결정 직전이라 예시가 실제처럼 읽힐 위험이 가장 큼 → **메인에만 쓰고 상세에는 실제 데이터가 생긴 뒤에** 권장 |
| ⑤ 실시간 활동 피드 | "방금 마포구에서 갤럭시탭 써보기 시작" | — | **비권장**(예시 표시를 붙여도 실제 활동처럼 보여 기만 위험 큼) |

## 예시 데이터를 만들어 보니 드러난 개발 방향(실제로 모아야 할 데이터)
| 보여 주고 싶은 것 | 지금 DB에 있는가 | 필요한 개발 |
|---|---|---|
| 써보고 구매/반납 결과 | 있음(trial_reviews.outcome, orders 상태) | 집계만 만들면 됨 |
| 써본 시간·체험료 | 있음(trial_reviews.hours, orders.trial_fee) | 집계만 |
| 반납 이유 | 있음(RETURN_REASONS 7종) | 집계만 |
| 써보기 스타(체험 만족 점수) | **없음** — 별점은 거래 후기(판매자·구매자 평가)에만 있음 | 써보기 후기에 "써보니 만족도"(10점) 추가 |
| 확인한 점 칩("화면 멍 없음 확인" 등) | 일부 — 종류별 질문 답변(answers JSON)은 있으나 칩 형태 아님 | 상품 종류별 "써보며 확인한 점" 칩 목록(노트북·태블릿·이어폰…) 추가 |
| 일반 중고보다 좋았던 점 | **없음** | 써보기 후기에 "써보니라서 좋았던 점" 칩(하자 걱정 없음, 실제 크기·무게 확인, 반납 부담 없음 등) 추가 |
| 한 줄 후기 | 있음(learned·reason 텍스트) | 공개 범위·글자 수 정리 |

→ 써보기 후기 양식에 **만족도 점수 + 확인한 점 칩 + 좋았던 점 칩** 세 가지를 더하면 ②③④ 모듈을 그대로 실제 데이터로 채울 수 있다.

## 만드는 방식(권장)
- 예시 데이터는 DB에 넣지 않고 별도 파일(예: demo-content.json)로 둔다(실제 데이터와 섞지 않음).
- 화면은 실제 데이터 우선: 실제 써보기 후기가 3건 미만이면 예시를 "예시" 표시와 함께 보이고, 3건 이상이면 실제만, 10건 이상이면 예시 영역 제거(기준은 설정값).
- 숫자 띠는 실제 완료된 써보기가 30건 이상일 때 실제 숫자로 바꾼다(그 전에는 예시 표시).
- 운영자 화면에서 예시 노출을 켜고 끌 수 있게 한다.

## 실제 데이터를 빨리 만드는 방법(병행 권장)
- 써보니 체험단: 지인·직원 10명 내외가 실제로 써보기 거래를 하고 실제 후기를 남긴다. 화면에는 "써보니 체험단 · 체험료 지원" 처럼 경제적 이해관계를 표시(지침상 의무).
- 사장님 상품(한군 계정 206개) 중 인기 모델 5~10개를 써보기 조건으로 열어 첫 실제 기록을 만든다.
