거래 핵심 범위
- 구매·써보기 신청. 신청 시점 조건을 저장하고, 체험 전 궁금한 점을 3개까지 고른다.
- 판매자 정산 계좌. 계좌번호는 암호화해 저장한다.
- 입금 확인 → 발송 → 받음 → 써보기 → 구매 확정 또는 반납 → 반송(맡긴 날 기록) → 검수(구성품 체크) → 환불 보냄 → 환불 받음.
- 상태가 바뀔 때마다 채팅방에 안내 메시지를 남긴다.
- 운영자 화면: 상태별 수, 최근 거래, 운영 확인, 설정.

예외 처리 범위
- 더 써보기(추가 입금 없음).
- 기한이 지난 경우: 입금 기한 자동 취소, 발송 뒤 자동 받음, 체험이 끝나면 확인 필요, 유예가 지나면 구매 확정.
- 기간을 넘겨 반납하면 다음 구간 체험료.
- 입금 뒤 취소하면 전액 환불.
- 분쟁: 자동 처리와 금액 확정을 멈추고, 운영자가 정리하며 환불액을 조정할 수 있다.
- 기한이 지난 일은 운영 확인으로 표시한다.

## 2. 안전장치

- 써보니는 돈을 받지 않는다. 구매자가 판매자 계좌로 직접 보내고, 화면과 문구에 이를 명시했다.
- 상태는 "예상 상태일 때만 바꾸는" 조건부 갱신이라, 같은 요청이 두 번 와도 한 번만 처리된다(시험: 입금 확인 두 번째 409).
- 경험치는 거래·회원·종류마다 한 번만 준다(유일 색인). 취소는 경험치가 없다.
- 공개 범위
  - 판매자 계좌 전체 번호: 입금 대기 중인 구매자에게만 보인다.
  - 배송지: 입금이 확인된 뒤에만 판매자에게 보인다.
  - 환불 계좌: 환불 단계에서만 판매자에게 보인다.
- 신뢰 기록은 횟수와 기간만 보여 주고, 기록이 없으면 "기록 없음"으로 표시한다. 정상 반납과 분쟁 신청만으로는 감점하지 않는다.
- 후기에는 보상을 주지 않는다. 연락처·계좌는 막는다.
- 거래 열기는 운영자 설정(tradeOpen)이고 기본은 닫힘이다. 격리 시험 서버는 별도 설정 파일을 쓴다.

## 4. 배포

- 실제 DB는 백업했다(E:\PROJECTS\04_써보니_backups\before-trade-*). 마이그레이션 0009_trade를 적용했다. 시스템 사용자(써보니)는 상태 SYSTEM이라 로그인할 수 없다.
- 수수료 설정을 베타 0%로 바꿨다(runtime-data/platform-fee.json). 운영자 화면에서 바꿀 수 있다.
- 공개 링크 확인: 홈, 상품 상세(거래 닫힘 → "써보고 싶어요", 시세 영역), /orders, /me/settlement, /sellers/[id] 모두 200.

## 5. 독립 검수 결과
- 1차 결과는 FAIL이었다(반드시 고칠 것 5건). 모두 고쳤다.
  1. 분쟁이 시간을 멈추지 않았다 → 분쟁 기간만큼 체험 끝·자동 처리 기한을 늦추고, 반납 체험료 계산에서도 뺀다(마이그레이션 0010).
  2. 운영자가 분쟁 결과를 바꿀 수 없었다 → "계속 진행 / 환불로 끝내기(금액) / 구매로 확정" 중에서 고른다.
  3. 입금 기한이 지난 거래가 상품을 계속 막았다 → 신청 전과 상품 조회 때 먼저 정리한다.
  4. 판매자가 상태를 바꾸는 요청과 새 신청이 동시에 오면 거래가 두 개 생길 수 있었다 → 거래 중 상품은 상태를 바꿀 수 없게 막는다(트랜잭션 안 조건).
  5. 분쟁 확인 직후에 금액 확정 행동이 통과할 수 있었다 → 상태를 바꾸는 조건 자체에 "열린 분쟁 없음"을 넣었다.
- 함께 반영한 권장 사항
  - 신청 시점의 판매자 계좌를 거래에 고정한다(거래 중 계좌 변경 사기 방지).
  - 시간 형식이 섞여도 목록이 바르게 정렬된다.
- 2차 재검수: 다섯 건 모두 확인됐다. 새로 나온 1건(분쟁 정리를 두 번 누르면 체험 시간이 두 번 늘어남)을 고쳤다. 낮은 등급 권장 2건도 반영했다(단계가 바뀌면 늦춘 기한을 초기화, 구매 확정 때 남은 환불 정보 지움).
- 반납 체험료는 사용 시간이 걸친 구간 요금으로 계산한다. 사용자 결정("25시간째는 48시간 요금")에 따른 것이라 그대로 두었다.
- 수정 확인 시험 16/16, 거래 전체 회귀 76/76, 단위 43/43.
- 독립 검수는 GPT 검수 도구가 300초 제한으로 실패해서 로컬 독립 검수 에이전트로 했다.

## 6. 승인이 필요한 것 (사용자 지시에 따라 모아서 보고)

1. 거래 열기: 운영자 화면 → 거래 → "거래 열기"를 체크하고 저장한다. 실제 돈이 구매자에서 판매자로 오가기 시작한다.
2. 거래를 열기 전 한군 계정의 정산 계좌 등록: MY → 정산 계좌. 사장님 본인 정보라 Claude가 입력하지 않았다.
3. 정식 수수료 전환 시점(지금 0%, 정식 3%).
4. 정본(main) 합치기.
5. 이전 회차 미결: 당근 상품 B급 추정값 확인, 써보기 허용 상품, 수수료 원 단위 처리.
