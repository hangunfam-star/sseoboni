## 1. 총평
안전장치와 정직한 표시가 뛰어나 실제 돈이 오가는 단계의 기준 문서로 쓰기 좋다. 다만 지금까지 사용자가 확정한 내용과 어긋나는 곳이 4군데 있어, 그대로 채택하기 전에 정리가 필요하다.

## 2. 특히 좋은 점 (그대로 채택 권장)
| 항목 | 이유 |
|---|---|
| 신청 시점 조건 저장(스냅숏) | 판매자가 나중에 가격·설명을 고쳐도 진행 중인 거래가 흔들리지 않는다. 지금은 제안 승인 때 판매자 조건만 기록하므로 거래 전체로 넓혀야 한다 |
| 체험 시작 = 수령 확인 시점 | 배송이 늦어 구매자 체험 시간이 줄어드는 불공정을 막는다 |
| 반송 기한 = 택배 인계 시점 | 택배 지연을 구매자 잘못으로 보지 않는다 |
| 반납 신청 ≠ 반납 완료 ≠ 환불 완료 | 상태를 거짓으로 앞당기지 않는다 |
| 중복 방지 | 환불·경험치를 거래번호 기준으로 한 번만 처리한다 |
| 부족액 자동 청구 금지 | 계산이 꼬여도 구매자에게 몰래 돈을 더 받지 않는다 |
| 분쟁 상태 분리 + 정산 보류 | 판매자 주장만으로 배상하지 않는다. 분쟁 신청만으로 감점하지 않는다 |
| 체험 전 질문 최대 3개 | 후기 때 그 질문을 다시 보여 주면 "써보고 알게 된 점"이 구체적이 된다. 써보니만의 후기가 된다 |
| 신뢰 = "9/10회 · 최근 90일" | 숫자, 분모, 기간을 함께 보여 준다. 없는 데이터를 만들지 않는 프로젝트 원칙과 맞는다 |
| 구매와 정상 반납 모두 정상 체험 인정 | 반납이 손해가 아니라는 써보니 철학과 맞는다 |
| 시세 = 중앙값·범위·건수·기간 | 평균보다 튀는 값에 덜 흔들린다. 표본이 적으면 "비교 거래 부족"으로 표시한다 |
| 판매자 구매 전환율은 본인 분석용 | 사이즈가 안 맞아 반납된 것 때문에 판매자가 불이익을 받지 않는다 |
| 후기에 보상 연결 금지 | 대가성 후기 논란을 피하고, 후기를 믿을 수 있게 된다 |

## 3. 기존 결정과 어긋나는 곳 (사용자 결정 필요)
| # | 수정안 | 기존 결정·현재 코드 | 분석 |
|---|---|---|---|
| A | 반납 환불액 = 결제금 − 체험료 − 택배료. 플랫폼 수수료가 없다 | 수수료 3%(특정 기간 0%). 사면 판매자 입금에서, 돌려보내면 환불금에서 뺀다 | 수수료가 빠지면 써보니 수익 구조가 없어진다. 실수로 빠진 것으로 보인다. 수수료를 다시 넣거나 없애기로 확정해야 한다 |
| B | 예시 최초 결제금 103,000원(상품가 + 배송비로 읽힘) | "10만원에 사면 구매자 10만원, 판매자 97,000원"(구매자는 상품 가격만) | 배송비를 최초 결제금에 넣을지 정해야 한다. 넣으면 구매자는 한 번 입금으로 끝나고(무통장에 유리), 화면에 상품가와 배송비를 나눠 보여 주면 된다 |
| C | 기한까지 무응답이면 "확인 필요". 자동 구매 안 함 | 가장 긴 구간을 넘기면 구매로 처리(사용자 선택). 25시간째는 48시간 요금 | 초기 베타에는 수정안이 더 안전하다. 권장: "확인 필요" + 안내 → 정한 유예(예: 72시간) 뒤에도 무응답이면 사전 고지한 대로 구매 확정. 구간 초과 요금(25시간 → 48시간) 처리도 수정안에 없으니 함께 정해야 한다 |
| D | 후기에 별점이 없다. 질문 답·결정 이유·한 줄·적합한 사람 + 거래 평가 항목 | 사용자 기획: 별점 1~10과 정해진 문구는 필수, 예시 문장과 직접 쓰기는 선택 | 둘을 합치는 것을 권장한다. 별점과 문구는 빠르게 쓰는 거래 평가로, 질문 답과 알게 된 점은 써보니 후기로 둔다 |

## 4. 수정안에 빠진 것
- 써보기 연장: 사용자 남은 작업 목록에 있다. 이미 전액을 결제했으므로 추가 입금 없이 다음 구간 차액만 환불금에서 줄이는 방식이 가장 단순하다.
- 수령 확인 방법: 택배 조회 연동이 없으므로 다음처럼 정해야 한다.
  1. 구매자가 "받았어요"를 누른다.
  2. 누르지 않으면 판매자가 발송한 뒤 N일이 지나면 자동으로 수령 처리한다.
  3. 이견이 있으면 운영자가 판단한다.
- 반송 인계 증빙: 송장번호와 인계 날짜를 입력하게 한다. 인계 날짜를 시스템이 자동으로 알 수 없으므로 영수증 사진을 함께 받는다.
- 무통장 운영
  - 고유 입금자명, 입금 기한과 자동 취소, 운영자 입금 확인을 정해야 한다.
  - 환불·정산 송금은 운영자가 직접 하고 "처리 완료"를 기록한다.
  - 이를 위해 돈의 흐름을 남기는 원장 표가 필요하다.
- 배송지·정산 계좌 같은 개인정보의 보관과 공개 범위
- 법·규제 확인(가장 큰 위험): 구매자 돈을 받아 두었다가 판매자에게 보내는 구조는 전자금융거래법(결제대행)과 전자상거래법(구매안전서비스) 적용 여부를 확인해야 한다. 수정안에는 이 내용이 없다.
- 카카오 공유: 남은 작업 목록에 있으나 수정안 범위 밖이다. 다른 작업과 무관해 따로 진행할 수 있다.

## 5. 이전 제안과 비교 (내 제안 중 바꿀 것)
| 이전 제안 | 수정안 | 판단 |
|---|---|---|
| 경험치 차등(써보기 +15, 높은 별점 +5) | 구매·반납 각 1점, 별점·가격·후기 보상 없음 | 수정안이 조작과 대가성 후기를 막는 데 더 낫다. 동기 부여가 약한 점은 등급 이름과 진행 막대로 보완한다 |

| 등급 이름(감별사·가게 계열) | 써린이 → 써본이 → 써잘알 → 써고수 → 써신 | 수정안 이름이 짧고 하나의 사다리라 이해하기 쉽다. 채택을 권장한다 |
