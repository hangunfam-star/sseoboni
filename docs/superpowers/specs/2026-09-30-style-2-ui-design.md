# 써보니 Gate 0 — Style 2 UI 디자인 명세

- 작성일: 2026-09-30
- 상태: 사용자 디자인 방향 승인 / 로컬 구현·화면 검증 완료 / 사용자 시각 검수 대기
- 적용 대상: `E:\PROJECTS\04_써보니\app`
- 기준 이미지: 사용자가 제공한 Task Manager 중심 UI와 Smart Home 카드·Today 타임라인 참고 이미지

## 1. 목표

현재 기능 위주의 기본 화면을 모바일 우선의 강한 카드형 UI로 바꾼다. 사용자가 처음 10초 안에 써보니의 핵심인 `사고 싶어요`, `써보고 싶어요`, `찾는 상품`을 구분하고, 한 화면에서 한 가지 주요 행동에 집중할 수 있어야 한다.

이번 1차 범위는 로그인, 공통 모바일 셸과 하단 메뉴, 홈, 찜 목록, 상품 상세다. 기존 인증·조회·찜 기능과 Gate 0 데이터 기록은 유지하며, 결제·실제 체험 신청·반환 기능은 만들지 않는다.

## 2. 디자인 해석

두 번째 참고 이미지의 Task Manager 스타일을 기본으로 사용한다.

- 큰 제목과 넓은 여백
- 24~32px의 큰 카드 모서리
- 흰 배경 위에 코랄·네이비·옐로 컬러 카드
- 카드 우측 또는 배경에 겹치는 원형·호 형태의 장식
- 짧은 설명과 명확한 상태 문구
- 화면 하단의 고정 메뉴와 주요 행동 버튼

첫 번째 이미지에서는 2열 카드 구성과 상태 토글의 명확성을 참고한다. 세 번째 이미지의 세로 타임라인은 향후 Gate 1의 써보기 과정 화면에만 사용하고, 이번 Gate 0 구현에는 포함하지 않는다.

## 3. 색상과 역할

| 토큰 | 값 | 역할 |
|---|---:|---|
| `--color-coral` | `#F2584A` | 써보고 싶은 의향, 따뜻한 강조 |
| `--color-coral-soft` | `#FFF0ED` | 써보기 관련 옅은 배경 |
| `--color-navy` | `#1B3A8C` | 구매 의향, 결정, 선택 상태 |
| `--color-navy-deep` | `#12265F` | 진한 텍스트·선택 카드 |
| `--color-yellow` | `#F6D74A` | 찾는 상품, 대기수요, 알림 |
| `--color-ink` | `#16181D` | 본문과 기본 버튼 |
| `--color-muted` | `#737780` | 보조 설명 |
| `--color-surface` | `#FFFFFF` | 카드 배경 |
| `--color-canvas` | `#F5F3F1` | 앱 전체 배경 |
| `--color-line` | `#E8E5E1` | 구분선 |

색만으로 의미를 구분하지 않는다. 코랄에는 항상 `써보고 싶어요`, 네이비에는 `사고 싶어요`, 옐로에는 `찾는 상품`처럼 텍스트를 함께 표시한다.

## 4. 기본 레이아웃

- 모바일 기준 폭: 360~430px
- 데스크톱에서는 중앙 정렬된 최대 480px 앱 셸로 표시
- 좌우 여백: 20px
- 상단 여백: 안전영역 포함 16~24px
- 하단 메뉴 높이: 72px + 모바일 안전영역
- 본문 하단 여백: 고정 메뉴와 겹치지 않도록 최소 104px
- 주요 버튼 높이: 56px
- 카드 모서리: 기본 24px, 히어로 카드 30px
- 그림자: 낮고 넓은 확산 그림자 하나만 사용
- 글꼴: `Pretendard`를 첫 번째 후보로 두고 시스템 한글 글꼴로 이어지는 로컬 글꼴 스택을 사용한다. 별도 웹폰트 의존성은 추가하지 않는다.

## 5. 공통 컴포넌트

### `MobileShell`

모든 공개 화면을 중앙 정렬하고 최대 폭과 안전영역을 관리한다. 현재 데스크톱형 상단 링크는 모바일 상단 브랜드 영역과 하단 메뉴로 교체한다.

### `BottomNav`

탭은 `홈 / 찾는 상품 / 판매하기 / 찜 / MY` 다섯 가지다. 현재 경로를 진한 네이비로 표시한다. `판매하기`는 가운데에서 약간 돌출된 코랄 원형 버튼으로 표현하되, 링크 기능은 기존 `/listings/new`를 사용한다. `찜`은 `/wishlist`에서 로그인한 사용자의 실제 찜 상품만 보여 주며, 비로그인 상태에서는 초대 코드 로그인 안내를 표시한다.

### `ColorCard`

코랄·네이비·옐로 카드의 공통 구조다. 제목, 짧은 설명, 선택적 보조정보, 우측 호 장식을 가진다. 장식은 CSS 의사요소로 구현해 이미지 파일을 추가하지 않는다.

### `ProductCard`

브랜드·모델, 상품명, 가격, 상태를 표시한다. 현재 실제 상품 사진 데이터가 없으므로 가짜 제품 사진을 넣지 않는다. 사진 필드가 없을 때는 브랜드 첫 글자와 모델명을 사용하는 중립적인 시각 플레이스홀더를 보여 주고 `사진 준비 중`을 명시한다.

### `ActionButton`

- 네이비: `사고 싶어요`
- 코랄: `써보고 싶어요`
- 옐로 또는 흰색 보조형: `이 상품 기다릴래요`

Gate 0에서 버튼은 결제나 거래를 시작하지 않고 의향만 기록한다. 완료 토스트에는 `의견이 기록됐어요`처럼 실제 동작을 설명한다.

## 6. 화면별 설계

### 6.1 로그인 `/login`

상단에 `사기 전에, 써보니.`를 큰 제목으로 표시한다. 그 아래에 세 개의 짧은 카드로 다음을 설명한다.

1. 네이비 — 사고 싶은 중고제품 찾기
2. 코랄 — 써보고 싶은 마음 남기기
3. 옐로 — 찾는 상품 기다리기

초대 코드 입력은 화면 하단 흰 카드에 배치한다. `지금은 테스트 기간이며 결제와 배송은 일어나지 않아요`를 입력창 위에 명확히 표시한다. 기존 초대 코드 로그인 요청과 오류 처리는 변경하지 않는다.

### 6.2 공통 상단과 하단 메뉴

상단은 텍스트 로고 `써보니`와 짧은 페이지 제목만 둔다. 로그인 링크는 MY 화면으로 이동시키고, 공개 화면에서 상단 링크 나열을 제거한다. 하단 메뉴가 없는 로그인 화면을 제외하면 모든 공개 화면에 동일한 하단 메뉴를 표시한다.

### 6.3 홈 `/`

순서는 다음과 같다.

1. 큰 제목: `오늘은 어떤 물건을 찾고 있나요?`
2. 둥근 검색창
3. 옐로 요약 카드: `사람들이 찾고 있어요` — 실제 수요 데이터가 연결되기 전에는 숫자를 만들지 않고 안내 문구만 표시
4. 최신 상품 영역: 실제 ACTIVE 상품만 `ProductCard`로 표시
5. 빈 상태: `아직 등록된 상품이 없어요`와 `찾는 상품 남기기` 버튼

상품 카드는 모바일에서 한 열을 기본으로 하고, 폭이 충분하면 두 열을 허용한다. 가격을 가장 굵게 표시하고 상태 등급은 작은 배지로 둔다.

### 6.4 상품 상세 `/listings/[id]`

상단에 중립적 상품 비주얼 영역, 브랜드·모델, 제목, 가격, 상태, 설명 순서로 배치한다. 실제 이미지가 없으면 플레이스홀더를 사용한다.

하단 고정 행동 영역은 찜 1개와 의향 버튼 2개, 총 세 행동으로 구성한다.

- 보조: 찜
- 네이비: `사고 싶어요`
- 코랄: `써보고 싶어요`

현재 코드의 비활성 `써보기 신청` 버튼은 실제 체험 신청처럼 보이므로 사용하지 않는다. 대신 Gate 0 의향 기록 기능이 준비되기 전까지 코랄 버튼을 `써보고 싶어요 · 준비 중`으로 표시하고, 클릭 시 거래가 시작되지 않는다는 사실을 분명히 한다. 구현 시 기존 API와 이벤트 구조를 확인해 기록 가능한 범위만 활성화한다.

### 6.5 찜 `/wishlist`

로그인한 사용자의 `wishlists`와 실제 `ACTIVE` 상품만 조회해 `ProductCard`로 표시한다. 찜이 없으면 숫자를 만들지 않고 `아직 찜한 상품이 없어요`와 홈 이동 버튼을 보여 준다. 로그인하지 않은 사용자는 빈 목록을 사용자의 목록처럼 보여 주지 않고 `초대 코드로 로그인하면 찜한 상품을 모아볼 수 있어요`와 로그인 버튼을 표시한다.

## 7. 상태와 예외 처리

- 로딩 중: 카드 크기를 유지하는 단순 스켈레톤 사용
- 상품 없음: 빈 카드와 다음 행동 하나만 표시
- 검색 결과 없음: `찾는 상품 남기기`로 연결
- 로그인 오류: 입력 카드 바로 아래에 짧은 오류문 표시
- 숨김·존재하지 않는 상품: 상품 정보를 보여 주지 않고 종료 안내 표시
- 긴 제목과 가격: 두 줄 말줄임과 숫자 줄바꿈 방지
- 네트워크 실패: 성공처럼 보이지 않도록 상태를 유지하고 재시도 안내

## 8. 접근성과 반응형

- 터치 영역 최소 44×44px
- 본문 텍스트 최소 15px, 보조 텍스트 최소 13px
- 텍스트 대비 WCAG AA 수준 유지
- 포커스 테두리를 제거하지 않는다
- 장식 호는 스크린리더에서 숨긴다
- 360px, 390px, 430px에서 가로 스크롤이 없어야 한다
- 데스크톱에서 모바일 앱 셸이 지나치게 늘어나지 않아야 한다

## 9. 구현 구조

새 UI 프레임워크나 Tailwind를 설치하지 않는다. 현재 Next.js 구조에서 CSS 변수와 재사용 컴포넌트로 구현한다.

예상 변경 범위:

- `app/src/app/globals.css` — 토큰, 모바일 셸, 카드, 버튼, 반응형 규칙
- `app/src/app/layout.tsx` — 공통 모바일 셸과 메뉴 적용
- `app/src/app/login/page.tsx` — 스타일 2 로그인 화면
- `app/src/app/page.tsx` — 홈 검색·요약·상품 카드
- `app/src/app/wishlist/page.tsx` — 로그인 사용자의 실제 찜 목록과 정직한 빈 상태
- `app/src/app/listings/[id]/page.tsx` — 상세 레이아웃
- `app/src/components/` — 공통 셸, 하단 메뉴, 카드, 버튼 컴포넌트

기존 미커밋 인증·초대 코드 변경은 보존한다. 데이터 스키마와 API는 이번 디자인 적용만을 위해 변경하지 않는다. 의향 기록 API가 필요한 경우에는 별도 기능 범위로 분리한다.

## 10. 검증 기준

1. `npm run lint`, TypeScript 검사, production build 통과
2. 기존 초대 코드 로그인과 상품 조회·상세·찜 동작 유지
3. 360px, 390px, 430px 모바일 화면 캡처 확인
4. 가짜 상품 사진·거래수·신뢰도·체험료가 표시되지 않음
5. Gate 0 화면에서 결제·배송·반환 또는 실제 체험 신청이 시작되지 않음
6. 다섯 개 하단 탭이 모두 실제 경로로 연결되고 모바일 안전영역과 겹치지 않음
7. 찜 화면은 로그인 사용자의 실제 찜 상품만 표시하고 비로그인·빈 상태를 사실대로 안내함
8. 로그인·홈·찜·상세의 색상 역할과 카드 스타일이 일관됨

## 11. 이번 범위에서 제외

- Gate 1 써보기 기간·비용·타임라인 화면
- 결제, 배송, 반환, 분쟁 처리
- 테스트 미션과 주간 진행률 기능
- 관리자 화면 디자인 개편
- 실제 상품 이미지 업로드와 저장 구조
- 데이터가 없는 수요 숫자와 사회적 증거 표시
- 외부 UI 라이브러리와 웹폰트 설치
